# 输入论文名称，创建从零实现课程

## 如何开始新 session

在 Codex 中选择 `/Users/max/codebase/scratch/tutorial` 项目并新建 session，输入论文名称、算法名或链接即可，例如 `I-JEPA`。根 AGENTS.md 将这一输入解释为创建或完善教学课程；无需粘贴旧对话。终端用户也可先进入仓库再运行 `codex`。

此行为依赖新 session 在本项目中读取根 AGENTS.md。[OpenAI 官方说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md) 描述了 session 启动时从项目根到当前目录读取指令的规则。其他目录中的 session 不自动具有本仓库约定。规划模式先产出方案，执行模式可创建课程。

## 默认学习者与目标

- 学习者理解基本 Python/PyTorch，但尚不能从一个空 def 独立设计整套模型。未知基础给出前置练习链接，不先要求用户自评水平。
- 中文讲解，细步骤与三级可选提示；核心计算让学生填写，初始化、数据准备、批量循环、padding 和训练外围骨架按需提供。
- 默认是 CPU 合成数据上的论文核心机制实现。另给真实数据、外部权重、资源与评估的递进路线，不能将 toy 或 recipe 配置称为论文指标复现。
- 基础算法复用 edu_core；新的通用基础组件只在确实被需要时补充。论文专属策略、损失和路由保留在课程内部。

## 1. 定位论文和现有课程

先检查 Git 状态、已有填答、课程地图、共享 API 和相近课程。若已有同版本课程，补缺口并保留学生答案；若请求明确不同版本，使用独立目录，避免替换旧算法。

检索并实际阅读原论文相关章节和官方实现。记录准确题名、作者/年份、版本、论文链接及官方仓库；关键机制尽量指向章节或源码。没有官方实现时以原论文为依据，并明确这一事实。不能从第三方摘要猜测结构、损失或消融结论。

明确名称通常采用原始同名论文，不自动升级为最新后续版本；当前已有版本约定优先。同名缩写对应不同算法时，给出具体候选并只询问必要的身份信息。识别唯一后简要说明采用哪篇，然后继续工作。

## 2. 将机制拆成课程

先画出输入 → 表征 → 关键模块 → 监督目标 → 参数更新的数据流，标出形状、可训练参数、stop-grad、mask 语义。列明本课程保留的论文机制与 toy 简化。

每个大机制拆成小函数或方法；每个微任务给输入/输出、目的、公式/轴推导、小例子、编号 TODO、错误提示和独立检查。遇到复杂采样、批量 packing 等任务，先给确定性单样本练习，再提供外围工程骨架连接完整流程。不要仅在空 def 上附一句“参考 reference”。

三级提示依次为思路、张量操作步骤、伪代码；放在 HINTS.md 中按需展开。基础不重复设置论文 TODO，课程说明何时应先做 foundations。

## 3. 实现与接线

按领域放入 `mllm/<paper>/` 或 `generative_model/<paper>/`。新目录名采用明确的 snake_case 算法名，版本需区分时带版本标识；先检查是否已存在。

课程至少包含：

|产物|职责|
|---|---|
|README.md|版本/来源、前置、数据流、形状、学习顺序、命令、简化与真实复现路线|
|reference_<paper>.py|完整可运行参考实现；保留核心机制并注明简化|
|lesson*.py + HINTS.md|分解练习、模块骨架与三级提示|
|practice_<paper>.py|组合学生函数；提供 `build_toy_<paper>()`，说明返回类型|
|check_lessons.py|`--lesson N` 检查指定关；省略遍历各关；默认 practice|
|run_<paper>_demo.py|`--implementation reference\|practice`，默认 reference；两模式相同机制验收|
|接线验证|用测试替身证明学生入口及训练步骤实际被调用；替身不写入 lesson|
|recipe/|真实训练配置、配置检查与复现条件说明；未实现能力明确标出|

practice 可以复用外围 toy backbone，但正在练习的机制不得转调答案；用显式注入或方法覆盖接线。不得捕获 TODO 后静默回退参考实现。参考模式必须独立于未完成练习运行。

对于生成模型也使用同样教学合同；读取 mllm/AGENTS.md 了解课程质量要求，但模型归属和训练工具按其领域处理。不要为接线强改已有 checkpoint 参数布局。

## 4. 验证并更新索引

先确认当前解释器与依赖，再运行静态编译、共享组件相关测试、逐关参考检查、参考 demo 和练习接线验证。局部检查用可手算数值、token 次序、信息隔离、配对、梯度边界与参数更新，不能只断言 shape。

用未完成练习确认 TODO 定位和非零退出码；用测试替身验证组装，可在测试中模拟完成练习，但不得把答案写回 lesson。真实填答验收保留给学习者。若依赖或论文资料缺失，准确记录未验证部分，不编造成功结果。

新增 MLLM 课程时同步更新 mllm/README.md 和 mllm/check_tutorials.py 的 DEMOS/WIRING 注册；其他领域更新对应索引与运行入口。不要改动既有学习成果。更新项目验证状态时保留旧结果日期，未重跑的旧课程结果不得标成新验证。

最后用简短中文报告采用的论文版本、课程路径、完成内容、实际验证和第一条练习命令。继续遵守用户额外给出的约束，不额外索要已确定的偏好。
